# Constitution — Game Concept and Win Condition

## Node

- Path: `.spec-tree/game-concept-and-win-condition/`
- Depth: 1
- Parent: `.spec-tree/root/`
- Priority: P1 with P2 impact

## Purpose

This branch defines the game promise, win-condition clarity, loss explanation, comeback requirements, anti-passive-play direction, and anti-spreadsheet guardrails. It does not implement the game.

## Governing Rules

1. The selected concept must be strategic, not speed/reflex based.
2. The win condition must be understandable in the first match.
3. The match must not end early only because a player reaches a score threshold.
4. The leader state, comeback path, and danger state must be visible.
5. The design must support 1v1v1v1 and 2v2 later.
6. The concept must support simultaneous planning or actions without turn waiting.
7. The concept must not require area control as a mandatory genre.
8. The result must feel like a game with meaningful board/arena/tokens/feedback, not a UI table.
9. The branch must reach depth 4 through meaningful child nodes.

## P1/P2 Quality Bar

- The player can answer: “What am I trying to do?” within seconds.
- The player can see: “Am I close to winning?” during the match.
- The player can understand: “Why did I win or lose?” after the match.
- Comeback routes must be built into the concept, not added as a late balance patch.
- Presentation must visualize progress and threat through game objects, not only numbers.

## Implementation Boundary

No Godot project, gameplay code, production art, or audio is authorized by this node. This node produces decisions, child-node scope, tasks, and acceptance gates.
