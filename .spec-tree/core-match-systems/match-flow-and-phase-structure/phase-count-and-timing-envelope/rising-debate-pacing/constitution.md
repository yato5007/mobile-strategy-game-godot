# Constitution — Rising Debate Pacing

## Node Identity

- Node: `.spec-tree/core-match-systems/match-flow-and-phase-structure/phase-count-and-timing-envelope/rising-debate-pacing/`
- Depth: 4 leaf.
- Parent: `.spec-tree/core-match-systems/match-flow-and-phase-structure/phase-count-and-timing-envelope/`
- Scope: Phases 4-6 of the fixed 9-phase Majlis match.

## Non-Negotiable Principles

1. No child nodes may be created because this is already depth 4.
2. No Godot game code, scenes, assets, tests, or export configuration may be implemented by this node.
3. Phases 4-6 must remain strategic, simultaneous, and readable; they must not become reaction-speed play.
4. The mid-match must create visible pressure and strategy-shift opportunities without mathematically deciding the match before phase 7.
5. FFA and 2v2 share one timing envelope but receive different attention cues.
6. All player-facing text requirements must be localizable for Arabic RTL and English LTR.
7. Mid-match pressure must appear as game objects and HUD cues, not spreadsheets or table-only data.

## Quality Bar for This Depth-4 Leaf

This leaf is complete only if it includes:

- A concrete phases 4-6 timing table.
- A concrete gameplay decision for Rising Debate cadence.
- UI/game-object outputs for leader threat, pressure, strategy shift, and teammate awareness.
- FFA and 2v2 differences.
- Godot-facing acceptance criteria without code.
- Validation rules and future metrics.
- Integration notes covering state machine, Claim state, action economy, multiplayer/bots, balance, and presentation.

## Boundaries

This node defines timing and attention contracts only. Exact Claim formulas, action legality, conflict resolution, bot decision models, network reconnect policy, and final victory/tie rules remain owned by future sibling branches.
